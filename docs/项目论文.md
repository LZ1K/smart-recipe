# Smart Recipe 智能菜谱助手 — 项目论文

---

## 一、选题动机

### 项目特色

Smart Recipe 不是一本死菜谱书。现有菜谱 App 基本上做的是同一件事——按标签筛选、按热度排序、把 200 道菜推成一样的列表。Smart Recipe 走的是另一条路：**让推荐由外部世界和你的个人偏好共同决定**。它接入了天气（wttr.in）、季节食材价格两个外部数据源，同时从对话中自动学习用户的口味偏好——高温天不推红烧肉、白菜当季便宜时优先推荐、你说过"不吃辣椒"它就记住并追问"那青椒甜椒呢"。

### 目标用户

25-40 岁的城市家庭做饭人。ta 不是专业厨师，但需要每天为家人做一两顿饭。典型场景是：下班路上或者站在冰箱前，不知道做什么、不知道外面 39 度是不是该放弃开火、更不知道今天什么菜便宜。

### 解决的实际痛点

1. **菜谱推荐跟你无关**：你爱吃什么忌什么，App 不知道，每次都推一样的。
2. **推荐脱离现实**：39 度高温天推火锅，冬天推凉拌菜，没有工具考虑天气因素。
3. **食材价格不透明**：番茄从 3 块涨到 8 块，没有 App 告诉你"现在别买番茄，换黄瓜吧"。
4. **AI 一刀切理解偏好**：你说不吃辣，它连青椒都不推——但青椒根本不辣。

## 二、项目目标与范围

### 核心功能清单

| 功能 | 说明 |
|------|------|
| 用户认证 | 邮箱注册/登录，JWT 策略，路由保护 |
| 菜谱浏览 | 20 道中式菜谱，分类筛选、关键词搜索、卡片列表 |
| 菜谱详情 | 食材清单 + 烹饪步骤 + 小贴士 + 营养信息 + 推荐搭配 + 常见问题 |
| 收藏管理 | 收藏/取消菜谱，收藏夹独立页面 |
| AI 对话 | DeepSeek SSE 流式对话，菜谱推荐和烹饪指导 |
| 偏好记忆 | 对话中自动提取口味/食材偏好，下次对话自动载入，持续修正 |
| 食材关联追问 | 区分口味偏好 vs 食材忌口 vs 过敏源，按关联图谱追问 |
| 天气驱动推荐 | 浏览器自确定位 → 获取实时天气 → 异常检测 → 标签加权倾斜推荐 |
| 季节推荐 | 当月当季食材清单 + 价格 + 优先推荐分类 |
| 价格预警 | 食材月环比涨幅 > 30% 或跌幅 > 25% 时主动提醒 |
| 对话历史管理 | 历史对话列表、点击切换、悬停删除、URL 跟随 |
| 个人中心 | 账号信息 + 偏好查看 |

### "智能"体现在哪里

| 维度 | 体现 |
|------|------|
| **感知外部世界** | 天气数据驱动推荐权重，39°C 倾向清淡菜、≤0°C 倾向炖煮暖身菜。四级降级（API→缓存→推算→默认）保证永远有数据 |
| **理解真实偏好** | 区分四类偏好（TASTE 口味/FAVORITE 食材/AVOIDANCE 忌口/ALLERGY 过敏），不搞一刀切。"不爱辣味"≠"不吃辣椒"≠"不吃青椒" |
| **持续学习** | 每次对话自动提取偏好（confidence≥0.7），去重入库，下次对话自动拼入 system prompt。对话越多，推荐越准 |
| **数据驱动决策** | 推荐不是模型内部黑箱权重，而是天气、菜价、季节、口味、食材喜恶五个可解释维度共同决定 |
| **主动预警** | 极端天气预警、食材保存提醒、价格暴涨暴跌提醒，不是被动等待用户问 |

## 三、技术选型概述

### 前端

| 选型 | 理由 |
|------|------|
| Next.js 16 (App Router + Turbopack) | 全栈框架，Server Component + 流式渲染天然支持 SSE 聊天。Turbopack 开发构建快 |
| shadcn/ui v4 (@base-ui/react) | 无头组件库，完全控制样式。v4 去掉了 asChild，用 buttonVariants 替代 |
| Tailwind CSS 4 | 原子化 CSS，配合 shadcn/ui。暖色调设计系统（橙/棕/米色）通过 CSS 变量实现 |
| Noto Sans SC + ZCOOL KuaiLe | 中文优先字体，正文 + 标题，无 Geist 等西文默认字体 |

### 后端

| 选型 | 理由 |
|------|------|
| Next.js API Routes | 与服务端渲染同一进程，无需单独后端服务 |
| Auth.js v5 (Credentials + JWT) | 邮箱密码认证，JWT 策略（无状态，不依赖数据库 session 表） |
| Zod v4 | 输入校验，v4 的 `error.issues`（非 `error.errors`）和 `z.record()` 语义 |
| proxy.ts | Next.js 16 推荐替代 middleware.ts 的路由保护方案 |

### AI 服务

| 选型 | 理由 |
|------|------|
| DeepSeek API | 中文效果好，价格低。通过 openai SDK 调用（兼容 OpenAI 协议），baseURL 指向 DeepSeek |
| SSE 流式输出 | `ReadableStream` + `TextEncoder`，前端 fetch + ReadableStream 接收逐字输出 |
| jsonMode | 偏好提取用 `response_format: { type: "json_object" }` 保证结构化输出 |

### 数据层

| 选型 | 理由 |
|------|------|
| PostgreSQL | 关系型数据库，支持 JSON 字段（菜谱的 ingredients/steps 存 JSON），联合索引加速偏好查询 |
| Prisma 7 + @prisma/adapter-pg | Prisma 7 必须传 driver adapter。用 pg Pool 直连，连接池上限 10 |
| 本地数据库（开发）/ Neon（上线） | 开发用本地 PostgreSQL，生产环境支持 Neon 云数据库 |

### 外部数据

| 选型 | 理由 |
|------|------|
| wttr.in | 免费天气 API，无需注册，支持坐标查询和反向地理编码 |
| Unsplash API | 菜谱实物图自动匹配，20 张全命中 |
| 自建季节食材数据 | 12 个月 × 8 种食材 = 96 条价格记录，基于全国农贸批发市场均价 |
| 浏览器 Geolocation API | 自动定位，localStorage 缓存 30 分钟，减少授权弹窗 |
